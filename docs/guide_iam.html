1. Qu'est-ce que IAM-Local ?

IAM-Local est une plateforme PHP d'identité et de contrôle d'accès (Identity & Access Management) pensée pour un environnement d'évaluation local (WAMP / XAMPP). Elle centralise :

  • les comptes utilisateurs (identités) ;
  • les applications protégées par authentification unique (SSO) ;
  • les rôles et permissions par application ;
  • les organisations (hiérarchie ministère → direction → service) ;
  • la politique de mots de passe, les sessions et le journal d'audit.

1.1 Vocabulaire essentiel

TermeDéfinition
IdentitéCompte d'un utilisateur (nom, e-mail, identifiant, matricule...).
ApplicationSystème tiers (ex. « Gestion des Présences ») protégé par l'IAM.
SSOAuthentification unique : une seule connexion IAM donne accès à toutes les applications autorisées.
RôleRegroupement de permissions (ex. « Directeur », « Agent », « Auditeur »).
PermissionDroit précis dans une application (ex. salary.validate, presence.record).
OrganisationStructure hiérarchique (ministère, direction, service, bureau) à laquelle les utilisateurs sont rattachés.
Garde SSOFichier généré automatiquement par l'IAM qui protège les pages d'une application.

1.2 Deux espaces distincts

ℹ️ IAM-Local sépare l'espace utilisateur (portail, profil) de la console d'administration (réservée au rôle admin).

2b. Compte initial et accès

⚠️ Le mot de passe initial est affiché une seule fois à la fin de l'installation. Il n'est pas inclus dans ce guide : conservez-le dans un gestionnaire de mots de passe et changez-le à la première connexion.

Les comptes de démonstration dépendent des données chargées dans la base. Consultez Administration → Utilisateurs pour vérifier les comptes existants, leur état et leurs rôles; n'utilisez pas un compte de démonstration en production.

2. Installation de la plateforme

2.1 Prérequis

  • Serveur web Apache + PHP 8.x (WAMP, XAMPP) avec extensions pdo_mysql, mbstring, openssl.
  • Serveur MySQL 8 (port 3306 par défaut).
  • La plateforme copiée dans le dossier web (ex. htdocs/IAM-Local ou www/IAM-Local).

2.2 Déroulement

Avec Apache lancé, la plateforme redirige automatiquement vers install.php tant qu'elle n'est pas installée (présence du fichier .installed).

  1. Informations de plateforme : nom de la plateforme (ex. « IAM-Local ») et URL de base auto-détectée (ex. http://localhost/IAM-Local).
  2. Connexion MySQL : hôte (ex. localhost), port (3306), utilisateur (ex. root), mot de passe, nom de la base (ex. iam_local). La base et son schéma sont créés automatiquement.
  3. Compte administrateur : nom, prénom, identifiant, e-mail, matricule. Le mot de passe initial peut être laissé vide : il sera généré automatiquement au format Admin@XXXX. Il est obligatoire de le changer à la première connexion.
  4. Case « Données de démonstration (ADEN, Présences/Salaires) » cochée par défaut : ajoute les applications et rôles d'exemple.
  5. Cliquer sur Installer.
⚠️ À la fin de l'installation, l'écran affiche les identifiants de l'administrateur en clair : copiez-les immédiatement. Le mot de passe devra être changé au premier accès.

2.3 Réinstallation / mise à jour

Sur l'écran « Déjà installé », le bouton Réinstaller / mettre à jour (install.php?reset=1) ré-exécute l'installation de façon idempotente : le schéma et les données sont mis à jour sans destruction. Un nouveau secret JWT est généré, ce qui invalide les jetons précédents.

3. Première connexion

  1. Ouvrir http://localhost/IAM-Local/login.php.
  2. Saisir l'adresse e-mail, l'identifiant ou le numéro de téléphone du compte, puis le mot de passe.
  3. Cliquer sur Se connecter.
  4. Si c'est un premier accès (must_change_password), la plateforme force le changement de mot de passe via Mon profil → Changer le mot de passe.
  5. Vous arrivez sur le portail des applications.

3.3 Connexion sans mot de passe (OTP)

Depuis la page de connexion, le lien « Se connecter sans mot de passe » ouvre otp_login.php :

  1. Saisir son adresse e-mail ou son numéro de téléphone puis cliquer Recevoir mon code.
  2. Saisir le code à usage unique reçu par e-mail (valable 5 minutes, 5 essais max).
  3. Après vérification, la session est ouverte (le mot de passe n'est pas saisi).
  4. Code perdu ? Clien sur « Renvoyer le code » (?resend=1).
ℹ️ Ce mode est utile pour les comptes dont le mot de passe est oublié ou sur mobile, sans passer par l'administrateur. Les comptes peuvent aussi être verrouillés (comme pour une connexion classique) après trop d'échecs.

4. Le portail « Mes applications »

Après connexion, le portail liste les applications accessibles à l'utilisateur selon ses rôles :

  • chaque application est présentée sous forme de carte (icône colorée, nom, description, code) ;
  • le bouton Accéder lance la connexion SSO et ouvre l'application ;
  • un bloc Mes rôles affiche tous les rôles attribués.
ℹ️ Si l'utilisateur doit changer son mot de passe, un bandeau d'avertissement apparaît et l'accès est suspendu tant que le mot de passe n'est pas modifié.

4.1 En-tête et navigation

  • Avatar + nom + e-mail : lien vers Mon profil.
  • Déconnexion : clôture la session (révoquée en base, journal d'audit).
  • La section de navigation « Administration » n'apparaît que pour les administrateurs.

4.2 Accéder à une application

  1. Cliquer sur Accéder sur la carte de l'application.
  2. L'IAM vérifie que le compte a bien un rôle sur cette application (sinon refus).
  3. L'IAM émet un jeton temporaire et redirige l'utilisateur vers l'application.
  4. L'application crée sa propre session : l'utilisateur est connecté sans ressaisir son mot de passe.

L'accès direct à l'URL d'une application protégée (sans passer par le portail) fonctionne aussi : l'application protégée redirige automatiquement vers la page de connexion IAM puis ramène l'utilisateur sur la page demandée.

6. Gestion des utilisateurs

Menu Administration → Utilisateurs. La liste affiche : utilisateur (nom + e-mail), matricule, organisation, rôles par application, statut, badge MFA, dernière connexion et les actions.

  • Recherche : champ en haut de page (nom, e-mail, matricule).
  • Pagination : 15 utilisateurs par page.
  • Bouton « Nouvel utilisateur » : ouvre la fenêtre de création.

6.1 Créer un utilisateur

  1. Cliquer sur Nouvel utilisateur.
  2. Renseigner : Prénom*, Nom*, E-mail* (obligatoires), Téléphone, Identifiant (login) (vide = e-mail), Matricule, Organisation, Direction / Service / Fonction.
  3. Saisir un Mot de passe temporaire* respectant la politique (min. 8 caractères + majuscule + chiffre + spécial).
  4. Dans Rôles par application, choisir un rôle pour chaque application concernée (option « — Aucun — » possible).
  5. Cocher les Groupes éventuels dans la liste à cocher.
  6. Cliquer sur Créer.
ℹ️ À la création, le compte est créé avec le drapeau « changer le mot de passe à la prochaine connexion ». C'est l'utilisateur qui choisira son propre mot de passe.

6.2 Modifier un utilisateur

  • Clic sur l'icône ✍️ crayon d'une ligne.
  • Modifier prénom, nom, e-mail, téléphone, matricule, organisation, direction/service/fonction, groupes et statut (active, inactive, locked).
  • Ajuster les rôles par application.
  • Cliquer sur Enregistrer. Les rôles sont remplacés par la nouvelle sélection.

6.3 Réinitialiser le mot de passe

  • Clic sur l'icône 🔑 clé d'une ligne.
  • Saisir un nouveau mot de passe respectant la politique.
  • Cliquer sur Réinitialiser. L'utilisateur devra le changer à sa prochaine connexion.

6.4 Supprimer un utilisateur

  • Clic sur l'icône 🗑 corbeille (avec confirmation).
  • L'administrateur principal (id 1) ne peut pas être supprimé.

6.5 Import CSV

Dans la liste des utilisateurs, le bouton « Importer » ouvre une fenêtre : téléchargez le modèle CSV (bouton « Télécharger le modèle »), remplissez-le puis importez-le. Règles :

  • Utilisez le modèle fourni par le bouton Télécharger le modèle CSV. Les en-têtes sont : email, first_name, last_name, puis les champs facultatifs username, phone, matricule, organization, department, service, fonction et status.
  • Le séparateur point-virgule ou virgule est détecté automatiquement; l'encodage UTF-8 avec BOM est accepté. E-mail, prénom et nom sont obligatoires.
  • Les e-mails déjà utilisés sont ignorés. Les lignes incomplètes sont signalées; l'organisation est recherchée par code ou nom.
  • Un mot de passe aléatoire est créé et le changement au prochain accès est exigé. Distribuez les accès par un canal sûr.

6.6 Gérer les groupes

Menu Administration → Groupes : créer, renommer ou supprimer des groupes (annuaires transverses, ex. « Encadrement », « Commission ») et gérer leurs membres. Les groupes sélectionnés dans un utilisateur apparaissent aussi dans les formulaires de création/modification (« Groupes »).

✅ Toutes ces opérations sont tracées dans le journal d'audit (user_created, user_updated, user_deleted, password_reset).

7. Gestion des applications & intégration SSO automatique

Menu Administration → Applications. Chaque application est présentée par une carte : icône colorée, nom, description, URL, badges d'état et boutons d'action.

7.1 Créer une application

  1. Cliquer sur Enregistrer une application.
  2. Renseigner les champs :
    ChampObligatoireDescription
    CodeouiIdentifiant unique (minuscules, tirets) ex. gestion-conges.
    NomouiNom affiché ex. « Gestion des Congés ».
    DescriptionnonTexte court affiché sur la carte.
    URLouiAdresse racine de l'application ex. http://localhost/App.
    Redirect URI (SSO)nonAutomatiquement <URL>/iam-sso-<code>.php si vide.
    CouleurnonCouleur de l'icône (défaut #4361ee).
    Icône (FontAwesome)nonClasse d'icône (défaut fa-cube).
    Active—Cochée : l'application peut être utilisée en SSO.
  3. Cliquer sur Enregistrer.

7.2 Déploiement SSO automatique

À la création (ou si l'URL change), l'IAM déploie automatiquement l'intégration SSO dans le dossier local de l'application :

  • génération d'un client_id (iam-native-<code>) et d'un client_secret unique ;
  • génération du fichier garde iam-sso-<code>.php à la racine de l'application ;
  • ajout dans le fichier .htaccess de l'application d'un bloc auto_prepend_file qui charge le garde sur toutes les pages PHP.
✅ Résultat : l'accès direct au lien de l'application redirige automatiquement vers l'IAM pour la connexion, puis ramène l'utilisateur sur la page demandée — sans aucune modification de code côté application.

7.3 Le panneau « Intégration SSO »

La carte de chaque application affiche l'état de la protection et propose :

Statut affichéSignification
Active (lien direct protégé)Fichier garde + .htaccess présents : protection active.
Fichier présent, .htaccess manquantLe garde existe mais le chargement automatique n'est pas en place.
Déploiement manuelApplication hébergée hors du disque local (serveur distant) : déploier le garde manuellement.
Non déployée / Dossier introuvableProtection à mettre en place ou chemin local non résolu.

Boutons disponibles :

  • Télécharger le fichier d'intégration → récupère iam-sso-<code>.php (pour un déploiement manuel).
  • Générer / redéployer → relance le déploiement (idempotent).
  • Retirer la protection → supprime le fichier garde et le bloc .htaccess généré.

7.4 Permissions de l'application

Le bouton Permissions (N) ouvre la gestion des permissions de l'application :

  • Modifier directement le nom, le code et la description d'une permission puis cliquer Enregistrer.
  • Supprimer une permission après confirmation; elle est alors retirée des rôles qui la portaient.
  • Ajouter une permission avec son nom*, son code* et une description.
Le code est unique dans toute la plateforme et peut être utilisé dans le code de l'application. Avant de le modifier, repérez ses usages et mettez-les à jour; testez ensuite l'accès autorisé et le refus des autres rôles.

7.5 Accès utilisateurs

Le bouton Accès utilisateurs (N) gère qui peut accéder à l'application :

  • Utilisateurs autorisés : liste des utilisateurs avec leur rôle et un bouton de retrait ;
  • Donner l'accès : sélection d'un utilisateur actif + d'un rôle, puis bouton Donner l'accès.

7.6 Supprimer une application

Bouton corbeille (les applications système, is_system=1, ne peuvent pas être supprimées).

⚠️ Pour une application hébergée hors localhost (serveur distant), le déploiement automatique est impossible (statut « Déploiement manuel ») : téléchargez le fichier garde et incluez-le via require_once __DIR__ . '/iam-sso-<code>.php'; dans les pages à protéger, ou déposez-le à la racine avec le .htaccess correspondant.

8. Rôles & permissions

Menu Administration → Rôles & permissions. Chaque rôle appartient à une application. Les cartes affichent le nom, le code, l'application propriétaire, la description, le nombre de permissions et le nombre d'attributions.

8.1 Profils standards

CodeProfilPrincipe d'accès
adminAdministrateurAccès complet à son application; seul le rôle admin de l'application iam-admin administre la plateforme.
gestionnaire_rhGestionnaire RHOpérations métier définies par les permissions de chaque application.
agentAgentConsultation uniquement; aucune création, modification, suppression ou validation.
auditeurAuditeurConsultation et export si l'application lui attribue une permission d'export; aucune écriture.

Des rôles métier propres à certaines applications peuvent compléter ces profils (par exemple employe, technicien, operateur ou magasinier). Un rôle affichant 0 permission ne donne aucun accès métier à un utilisateur non administrateur.

8.2 Créer un rôle

  1. Cliquer sur Créer un rôle.
  2. Saisir Nom du rôle* (ex. « Superviseur Paie ») et Code* (ex. superviseur_paie).
  3. Ajouter éventuellement une description.
  4. Cliquer sur Créer.

8.3 Attribuer des permissions

  1. Sur la carte du rôle, cliquer sur Permissions.
  2. La fenêtre présente les permissions groupées par application.
  3. Cocher/décocher les permissions souhaitées (badges cliquables).
  4. Cliquer sur Enregistrer.
ℹ️ Les permissions des rôles système peuvent être configurées graphiquement. Leur nom et leur code restent protégés, et leur suppression est interdite.

8.4 Supprimer un rôle

Bouton corbeille sur une carte de rôle non système (avec confirmation). Un rôle système ne peut pas être supprimé.

9. Organisations

Menu Administration → Organisations. Construit un arbre hiérarchique : ministère → direction générale → direction → service → bureau.

9.1 Types d'organisation

ministère direction_generale direction service bureau autre

9.2 Créer une organisation

  1. Cliquer sur Nouvelle organisation.
  2. Saisir Nom* (obligatoire), Code, choisir le type et l'organisation parente (« — Aucune (racine) — » pour une racine).
  3. Cliquer sur Créer.

9.3 Modifier / supprimer

  • Modifier (icône crayon) : nom, code, type, parent.
  • Supprimer : possible uniquement si aucun utilisateur n'est rattaché (« Cette organisation contient des utilisateurs. Déplacez-les d'abord. »).

Les utilisateurs sont rattachés à une organisation au moment de leur création ou modification (page Utilisateurs).

10. Sessions utilisateurs

Menu Administration → Sessions. Liste de toutes les sessions IAM actives avec : utilisateur, IP, navigateur (user-agent), création, dernière activité, expiration, statut et actions.

10.1 Statuts

StatutSignification
activeSession en cours, non expirée.
expiréeLa date d'expiration est dépassée.
révoquéeSession invalidée manuellement ou à la déconnexion.

10.2 Révoquer

  • Icône 🚫 rouge : révoque une session.
  • Icône 🚫 encadrée : révoque toutes les sessions d'un utilisateur (ex. matériel volé).
ℹ️ Filtre par utilisateur (select) + bouton Filtrer pour restreindre la liste. Les révocations sont journalisées (session_revoked, sessions_revoked).

11. Journal d'audit

Menu Administration → Journal d'audit. Trace exhaustive et horodatée des actions sensibles.

11.1 Filtres

  • Champ de recherche q (e-mail, action, détails, IP).
  • Select action : filtre par type d'événement.
  • Boutons Filtrer (🔍) et Effacer (retour à la liste complète).

11.2 Informations affichées

Date, action (badge coloré), utilisateur (e-mail + identifiant), détails, IP, navigateur. Si la géolocalisation est activée (geoip_lookup, voir « Paramètres »), une colonne pays apparaît (IP privée = « Réseau local »). Pagination : 30 lignes par page.

12.3 Informations plateforme (lecture seule)

La page affiche aussi les informations statiques : nom (IAM_NAME), version, URL, base de données, état SMTP et récapitulatif de la politique active.

ℹ️ Le SMTP sert à l'envoi des codes MFA par e-mail. Non configuré, l'IAM passe en mode démonstration : le code OTP s'affiche directement à l'écran.

14. Authentification à deux facteurs (MFA)

Lorsqu'un compte a la MFA activée, la connexion est suivie d'une vérification par code OTP à 6 chiffres :

  1. Connexion classique (identifiant + mot de passe).
  2. Redirection vers mfa.php : un code à 6 chiffres est envoyé par e-mail.
  3. Saisie du code puis bouton Vérifier et continuer.

14.1 Liens utiles

  • Renvoyer le code : émet un nouveau code.
  • Annuler : déconnecte et revient à la page de connexion.

14.2 Règles

  • Validité du code : 5 minutes.
  • 5 échecs maximum → la session est détruite et l'utilisateur renvoyé à la page de connexion (mfa_lockout tracé).
  • Mode démonstration : sans SMTP configuré, le code OTP est affiché directement à l'écran dans un encart orange.
⚠️ L'activation/désactivation de la MFA n'est pas exposée dans l'interface administrateur : elle se règle en base (colonne mfa_enabled de la table users).

15. Fonctionnement du SSO (référence technique)

Le SSO repose sur la rédemption d'un jeton à usage unique : l'IAM émet un jeton, l'application le consomme auprès de l'API IAM et ouvre sa session locale.

15.1 URL impliquées

AdresseRôle
IAM_BASE_URL/sso/authorize.php?app=<code>&return=<url>&prompt=loginPoint d'entrée SSO : vérifie l'accès et émet le jeton.
IAM_BASE_URL/login.phpConnexion utilisateur.
IAM_BASE_URL/mfa.phpVérification 2 facteurs (si activée).
IAM_BASE_URL/api/sso/validate.phpAPI POST JSON {token, app_code} : consomme le jeton et renvoie l'utilisateur, les rôles et les permissions.
IAM_BASE_URL/admin/download_sso.php?app=<code>Téléchargement du fichier garde.

15.2 Scénario : accès direct à une application protégée

  1. L'utilisateur ouvre http://localhost/Application/page.php.
  2. Le garde iam-sso-<code>.php (chargé par auto_prepend_file) démarre une session locale isolée iam_app_<code>.
  3. Non authentifié → redirection vers sso/authorize.php?app=<code>&return=<page demandée>&prompt=login.
  4. authorize.php envoie l'utilisateur sur login.php (ou force la ressaisie si prompt=login).
  5. Après connexion (et MFA / changement de mot de passe éventuels), retour sur authorize.php.
  6. authorize.php vérifie : application active, utilisateur avec un rôle sur l'app (ou admin global), URL de retour sur le même hôte que l'application.
  7. Jeton SSO à usage unique créé (validité 60 s) → redirection vers returnUrl?sso_token=….
  8. Le garde envoie le jeton à api/sso/validate.php, qui le consomme et renvoie access_token (JWT 1 h), profils, rôles, permissions.
  9. Le garde ouvre la session locale, retire sso_token de l'URL et affiche la page.
  10. Pages suivantes : iam_sso_authenticated() passe directement.

15.3 Fonctions fournies au développeur d'application

FonctionRôle

15.6 Serveur OAuth 2.0 / OIDC (Authorization Code + PKCE)

L'IAM expose aussi un serveur d'autorisation pour les applications « tout type » (SPA, mobiles, services) :

AdresseRôle
IAM_BASE_URL/oauth.phpDemande d'autorisation + page de consentement (paramètres response_type=code, client_id, redirect_uri, scope, state, code_challenge, code_challenge_method, nonce).
IAM_BASE_URL/api/oauth/token.phpPOST : échange du code (avec vérification PKCE) ou refresh_token (rotation : le jeton consommé est révoqué) ou client_credentials.
IAM_BASE_URL/api/oauth/userinfo.phpGET avec Authorization: Bearer <access_token> : profil OIDC (sub, name, email, poste…).
IAM_BASE_URL/api/oauth/jwks.phpClés publiques de vérification des JWT (RS256).
IAM_BASE_URL/.well-known/openid-configuration.phpDécouverte OIDC (issuer, endpoints, PKCE supporté).
  • Scopes autorisés : openid, profile, email.
  • L'id_token (JWT RS256) contient sub, aud (client), iss, exp, iat, nonce et les claims du profil demandé.
  • La gestion des clients et la rotation de clé se font dans Administration → OAuth / OIDC ; le secret du client n'est affiché qu'à la création.
  • Le consentement est demandé à l'utilisateur et le refus est journalisé (access_denied).

16. Bonnes pratiques & dépannage

16.1 Bonnes pratiques

  • Administrateur principal : conservez le compte (id 1) ; il ne peut pas être supprimé et doit rester l'ultime recours.
  • Mots de passe temporaires : utilisez le mot de passe généré aléatoirement par l'IAM et forcez son changement à la première connexion.
  • Rôles par app : attribuez le rôle le moins privilégié nécessaire (principe du moindre privilège).
  • Sessions : révoquez les sessions d'un utilisateur en cas de départ ou d'appareil perdu.
  • Audit : consultez régulièrement le journal pour détecter les accès anormaux.
  • Organisations : construisez l'arbre avant de créer les utilisateurs pour faciliter le rattachement.

16.2 Dépannage
